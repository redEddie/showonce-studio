# 04 정책 실행 · SDK와 작업 관리

상단 **실행 방식**은 매번 페이지를 열 때 **명령어 보기**로 시작합니다.
이 상태에서는 버튼을 눌러도 프로세스를 시작하지 않고 복사할 명령만 표시합니다.
복사용 명령에서는 기본 CAN 채널과 웹앱 관리 인자를 생략합니다. 저장 경로·작업 토큰은
명령창 위 작은 글씨로 분리하고 복사에 포함하지 않습니다. 명령창은 접거나 닫을 수 있습니다.
직접 터미널에서 정책을 실행할 때 `--out`을 생략하면 데이터 경로의 `runs/showonce-policy/` 아래에 자동 저장합니다.
웹에서 관리하는 직접 실행은 별도 작업 경로와 PID 검증을 계속 사용합니다.
**바로 실행**을 선택한 뒤 누른 버튼은 별도 프로세스로 실행합니다.

## SDK 제어

- **Enable**: 팔 6축과 그리퍼 활성화. 실측 그리퍼 폭을 목표로 사용하며 force 기본값은 0.5입니다.
  영점 부근 음수 피드백은 -3mm까지 허용하고 목표만 0mm로 제한합니다. 실측값·목표값은 로그와
  결과의 `gripper_enable`에 기록하며, 영점 재설정이나 정책 관측 보정은 하지 않습니다.
  범위 밖(-3mm 미만 / 100mm 초과), 미수신·오래된 피드백, 폭 모드 불일치·오류 상태는 활성화하지 않습니다.
- **Disable**: 팔 6축과 그리퍼의 모터 전원 해제.
- **SDK Stop**: SDK의 감쇠 전자정지. 자세 유지나 정책의 부드러운 중단과 구분합니다.
- **Reset**: 팔 SDK reset 요청. 자동 enable이나 home을 이어서 실행하지 않습니다.
- **상태 조회**: 연결 후 수신한 모터·그리퍼·제어 모드·오류를 표시합니다. 기록 시각을 함께 표시합니다.
- **Mode**: 번호와 이름을 선택합니다. SDK로 선택 가능한 값은 0/1/3/4/7이고,
  티칭 등 로봇 버튼으로 전환하는 모드는 선택 불가 상태로 설명합니다.

현재 제어 유틸리티는 기존 SHOW-78 SDK 및 SHOW-100 mode/power 명령의 검증된 동작을 재사용합니다.
선택한 worker 환경에 `piper-runtime[robot]`의 SDK 의존성을 설치합니다.
`configs/local.toml`의 `[python].robot` 또는 `SHOWONCE_ROBOT_PYTHON`으로 전용 환경을 지정할 수 있습니다.
CLI는 `python -m showonce_studio.showonce_robot enable`처럼 사용합니다.
`mode --value 1`은 비대화 실행이고, 터미널에서 `mode`만 실행하면 번호를 입력할 수 있습니다.

## 수동 TCP · 그리퍼

현재 개선은 보류하며 패널을 기본적으로 접어둡니다. 외부 프로젝트를 참고한 후 개선할 예정이고,
기존 코드·기능은 보존합니다. 패널을 닫으면 조그 입력과 수동 연결을 종료하며 모터 전원은 바꾸지 않습니다.

04의 수동 패널은 베이스 좌표계 TCP(138.5mm)의 XYZ(mm)와 RPY(도)를 표시합니다.
바로 실행에서 **수동 연결 · 현재값 읽기**를 누르면 별도 worker가 피드백을 읽습니다.
연결만으로 enable, 목표 전송, 그리퍼 개폐를 하지 않습니다. 팔을 활성화하고 CAN 모드로 둬야 연결됩니다.
수동 worker에는 웹앱을 시작한 `--calib` 경로를 자동 전달합니다. 04의 현재 보정 파일 입력에도 표시하며,
입력을 바꾸면 그 경로를 우선 사용합니다. 수동 연결 때문에 보정을 새로 수행할 필요는 없습니다.
연결은 최대 10분이며, 연결 종료나 탭 이탈·통신 중단 시 입력 기한으로 종료합니다.

- XYZ는 누르고 있는 동안 이동하며 기본 10mm/s, 선택 범위 1~50mm/s입니다.
  상한을 변경한 뒤에는 기존 수동 연결을 종료하고 다시 연결해야 새 스케일을 사용합니다.
- 현재 자세에서 방향·위치를 유지하며 1mm 움직일 수 있는지 IK와 테이블 형상으로 검사합니다.
  불가한 방향만 비활성화하며 이유를 표시합니다. 피드백이 오래되면 조작 버튼 전체를 비활성화합니다.
- R/P/Y는 베이스 X/Y/Z축으로 각각 ±90° 회전합니다. TCP 위치를 고정한 5° 간격 IK 경로를
  사전 검사하며, 불가한 회전은 비활성화합니다. 표시 RPY는 xyz Euler 각이므로 특이점에서 숫자가 바뀔 수 있습니다.
- 이동에는 공통 SHOW-103 QP(관절 속도 1 / 가속도 5 / jerk 100)를 사용합니다.
  QP 참조·정지 경로의 관절 한계, TCP 테이블 +10mm, 팔 링크 +10mm와 그리퍼 테이블 침범을 검사합니다.
  기존 수평 작업영역 제한을 추가하지 않습니다. 주변 객체·팔 자기 충돌 전체 검사는 아닙니다.
- 버튼을 놓으면 입력을 해제합니다. 조그 갱신이 450ms 끊기면 QP의 검증된 경로로 감속하며,
  연결 heartbeat가 2초 끊기면 수동 연결도 종료합니다. SDK Stop/Disable은 기존 우선 중단을 사용합니다.
- 그리퍼는 목표 폭 0~100mm와 force 0.5~3을 명시적으로 적용합니다. 기본 force는 0.5입니다.
  연결 중에는 현재 팔 자세에서 개폐에 따른 테이블 간격을 검사하며 팔 목표는 바꾸지 않습니다.

명령어 보기에서는 아래와 같은 제한 시간 명령을 만듭니다. 웹 관리용 경로·토큰은 복사에서 제외합니다.

```bash
python -m showonce_studio.showonce_robot jog --axis z --direction -1 --speed-mm-s 10 --seconds 2
python -m showonce_studio.showonce_robot rotate --axis yaw --direction 1 --seconds 30
python -m showonce_studio.showonce_robot gripper --width-mm 50 --force 0.5
```

회전·이동에는 현재 보정 파일이 필요합니다. 터미널의 그리퍼 단독 명령은 기존 SDK 폭 제어이며,
수동 연결의 모델·테이블 검사 경로와 구분합니다. 새 수동 경로는 가짜 로봇/브라우저로 검사했으며
실제 로봇의 동작 검증은 아직 수행하지 않았습니다.

### 팔 풀기 · TCP 위치 고정

수동 패널의 **팔 풀기**는 시작 시 TCP 위치(XYZ)를 기준으로 잡고, 그리퍼 방향과 팔 자세를 바꿉니다.
TCP는 138.5mm 기준이며 그리퍼 폭은 유지합니다. 자코비안의 위치 영공간으로 자세 개선 방향을 만들고,
작은 관절 이동을 같은 TCP 위치로 투영합니다. 손목 중립·관절 한계 여유를 개선하는 경로만 선택합니다.
시작 관절이 모델·SDK 범위 밖이면 해당 관절과 허용 범위를 표시하고 실행하지 않습니다.

- **경로만 검사**: 목표를 전송하지 않고 계산한 경유점·방향 변화·위치 편차를 확인합니다.
- 계획 경로는 노드 사이도 검사하며 TCP 편차를 0.2mm 이내로 제한합니다.
- QP 참조와 전체 정지 경로는 시작 위치에서 1mm 이내인지 매번 검사합니다.
- 관절 피드백으로 계산한 TCP가 시작 위치에서 2mm를 넘으면 새 목표 전송을 중단합니다.
  이는 모델 기반 상대 위치 검사이며 물리적인 위치 정밀도를 보증하는 값은 아닙니다.
- 제약을 만족하는 자세 개선 경로가 없으면 실행하지 않습니다. TCP를 옮기는 경로로 대체하지 않습니다.
- 관절 목표 추종 속도는 0.12rad/s이며 공통 상한 v1/a5/jerk100은 유지합니다. XYZ 조그의 50mm/s 상한은 별개입니다.

위치 고정 방식은 **기존 수동 연결을 종료한 뒤 다시 연결**해야 적용됩니다.
이전 worker는 새 API와 UI에서 팔 풀기를 막으며, 이전 TCP 이동 경로 기록은 별도로 표시합니다.
`manual-route.json`과 작업 결과에는 기준 위치·계획 최대 편차·위치 허용 오차·관절 경유점을 저장합니다.
실행 결과에는 최대 참조/피드백 기반 TCP 편차도 기록합니다.

```bash
python -m showonce_studio.showonce_robot unwind --plan-only
python -m showonce_studio.showonce_robot unwind --seconds 60
```

모델·테이블 형상 검사를 사용하며 주변 물체·팔 자기 충돌 전체 검사는 포함하지 않습니다.
강화학습 정책과 공통 Runtime 제어기는 변경하지 않습니다. 실기 동작 검증은 별도입니다.

## 정책과 프로세스

등록 정책의 validate/mock/replay/shadow/run 명령을 만들거나 직접 실행할 수 있습니다.
실제 run/shadow에는 현재 보정과 `live_camera_only` 인식 폴더가 필요하며 저장 영상은 대신 사용할 수 없습니다.
정책은 검증 후 로봇 피드백·모터 상태·시작 자세를 확인하며 자동 enable/home을 보내지 않습니다.
제어 시간은 최대 60초이고 사전 확인은 제어 시간과 별도입니다.

작업 ID·PID·경과/제어 남은 시간·진행 단계·로그·결과를 저장합니다.
페이지를 새로고침하거나 다른 페이지로 갔다 돌아와도 작업 상태를 복구합니다.
탭을 닫아도 작업은 계속되며 설정 시간 후 종료합니다.
**정책 중단 (Ctrl+C)**은 소유한 프로세스 그룹에 SIGINT를 보내고, 제어 중에는 QP 감속 종료를 요청합니다.
인식을 기다리는 사전 확인 단계에서도 중단 요청을 확인합니다. 자동 damping/disable은 보내지 않습니다.

SDK Stop/Disable을 직접 요청하면 같은 채널의 관리 중인 전송 작업을 먼저 종료합니다.
감속 중단과 달리 추가 참조를 보내지 않는 우선 중단이며, 응답하지 않는 관리 작업은 강제 종료할 수 있습니다.
다른 프로그램이 보유한 CAN 채널에서는 Enable/Reset/Mode를 실행하지 않습니다.
프로세스 종료 자체가 물리적인 비상 정지를 의미하지 않으며 마지막 SDK 목표까지 움직임이 남을 수 있습니다.

작업 기록은 `SHOWONCE_HOME/runs/showonce-robot/`에 저장하며 PID 재사용을 확인해 다른 프로세스에 신호를 보내지 않습니다.
짧은 SDK 작업에도 제한 시간을 두고, 프로세스가 끝나기 전에는 완료 상태로 표시하지 않습니다.
웹 프로세스는 SDK를 import/연결하거나 200Hz 제어 주기를 처리하지 않습니다.
`--offline`에서는 실제 SDK/실기 연결을 막고 정책 CPU 검사만 사용할 수 있습니다.

## 검증 범위

SDK 버튼 경로는 주입한 가짜 SDK로 Enable/Disable/Stop/Reset/Read/Mode를 검증했습니다.
실제 SDK/CAN 명령은 개발 테스트에서 보내지 않았습니다.
CPU mock에서 새로고침 복구·SIGINT 중단을 확인했으며 이는 실기 정책 성공 검증이 아닙니다.

## 실시간 인식과 정책 입력 확인

04의 실시간 인식 패널은 기존 인식 노드의 `tracked_poses.json`, `diagnostics.json`,
`latest.jpg/png`를 읽습니다. 카메라 원본과 인식 오버레이를 구분하고, 관측 시각을 새로 붙이지 않습니다.
상시 인식이 구성된 장비에서는 Studio 시작 시 지속 worker에 연결합니다. SAM은 촬영 노드의 RGB-D를 구독하며 웹 새로고침/정책 교체로 다시 로드하지 않습니다. 설정이 없는 장비의 페이지 열기는 노드를 자동 시작하지 않으며, 로봇 명령은 항상 명시적으로 실행합니다.
정책 worker는 매 정책 호출의 실제 물체 입력/상태추정 출처를 `policy-input.json`과 이벤트 로그에
기록합니다. UI는 mock 값을 실측으로 표시하지 않으며, 종료된 실행은 과거 기록으로 구분합니다.
이 표시만으로 실패 원인이 정책이라고 자동 판정하지 않습니다.

명령은 `RobotActions.plan()`이 정책 ID·시간·보정·인식 폴더를 조합해 생성합니다.
연결이 준비되지 않은 shadow/run은 `command_ready=false`로 반환하여 복사를 막습니다.
실행 버튼 아래에서 명령/연결 오류를 확인하며, SDK 명령은 별도 SDK 영역에 표시합니다.

정책 호출마다 `policy-inputs.jsonl`에 물체 입력과 측정 관절 FK TCP를 기록합니다.
04의 XY 그래프는 이 파일을 커서 방식으로 읽어 브라우저 갱신 사이의 샘플도 보존합니다.
run/shadow 경로와 mock을 구별하며 mock 경로는 실측 궤적으로 표시하지 않습니다.

SDK Enable과 같은 3mm 닫힘 끝단 허용 범위를 정책 입력에도 적용합니다. -3..0mm 피드백만
0mm로 정규화하고 원본 signed 폭/적용 횟수를 보존합니다. 전체 개폐 범위에 offset을 빼지 않으며,
더 큰 음수·비유한 값과 시작 자세 A/개방 상태 검사는 기존대로 거부합니다.

## 시작 자세 A 복귀

04 실행 안내에서 Enable 다음에 **시작 자세 A로 이동**을 선택합니다.
명령어 보기에서는 `showonce-robot home`을 표시하고, 바로 실행에서는 별도 관리 프로세스가
Studio 내부 `home_control`/`posture_control`을 실행합니다. 외부 Home 실행기는 필요 없습니다.
기존 `home` CLI/API 이름은 호환을 위해 유지합니다.

제어 환경에 `showonce-studio[motion]`을 설치합니다. 시간 최적 참조(Ruckig 0.19.4)와 기존 SHOW-103 QP,
200Hz 전송, 관절 속도 1rad/s·펌웨어 가속도 상한·참조 jerk 100rad/s³, TCP 138.5mm를 유지합니다.
신뢰된 테이블 보정과 Runtime에 포함된 로봇 모델/간격 형상을 사용하며 TCP/팔 링크 간격은 10mm입니다.
모델 범위를 벗어난 관절의 기존 SDK 경계 복귀도 유지합니다.

기본 자세 A는 `[0, 0.523, -0.45, 0, 0, 0]` rad입니다. 정책을 선택한 경우 `--policy-id`로
그 정책의 `nominal_qpos`와 로봇 설정을 읽습니다. 기본 복귀에는 정책 패키지가 필요하지 않으며,
선택하더라도 actor 가중치를 읽거나 추론하지 않습니다.

```bash
showonce-robot home --calib /path/to/current.json
# Thor 운영 호환 명령
python showonce_robot.py home
```

최대 60초, force 0.5이며 그리퍼를 엽니다. 자동 enable은 보내지 않습니다.
실행 중에는 중복 복귀/정책 전송을 막습니다. 중단은 SIGINT 또는 `halt.now`로 새 목표 전송을 중지하며
자동 damping/disable을 보내지 않습니다. 마지막 SDK 목표까지 움직임이 남을 수 있습니다.
실측 피드백·참조·결과는 `runs/showonce-home/<시각>/motion/`에 기록합니다.
이번 이식은 CPU mock/명령 동등성으로 검증했으며 새 실기 이동은 실행하지 않았습니다.

## 별도 튜토리얼: 스크립트 파지

[웹앱 없이 실행하는 7단계 예제](../examples/scripted-grasp/README.md)는 선택 예제입니다.
정책 실행의 필수 구성이나 웹앱 제어 버튼에 포함하지 않습니다. 카메라/SAM 노드를 독립 실행하고
`showonce-scripted plan|run --perception-dir ...`로 실행합니다. 외부 스크립트 경로와 정책 가중치가 필요하지 않습니다.
